# SC-005 — reviewers see referenced definitions (US5, T050)

**Measured 2026-08-15** against `deepseek-v4-pro`, on the vendored gold-set
corpus (`tests/fixtures/gold_set_corpus`) rebuilt as a two-commit repository so
each hunk is a *window* into a larger file. A whole-file addition puts every
declaration inside the diff, which is the one condition under which these false
positives cannot arise — measuring there would have proved nothing.

SC-005 reads: *replay the gold set with related-file context on and verification
off, confirming the two false-positive classes are not generated at all.*

The honest answer is **one class measured and closed, one class not reproduced**.
Both halves are recorded below, including the half that did not work.

---

## What is proven deterministically

`tests/unit/test_reviewer_context.py` and `tests/integration/test_context_delivery.py`
assert the thing the harness controls: the declaration that refutes the false
claim is IN THE PAYLOAD that reaches the provider. Before this change it was not,
in any run, for any model.

`tests/proofs/context_mutations.sh` derives that those assertions can fail — 21
mutations, each removing one guard, each detected by its named test. That proof
runs in CI.

Whether a given model then still writes the finding is a question about the
model, which is what the live arms below address.

---

## The live measurement: three arms, one diff

The diff changes `commanderDedupKey` to trim names **and adds a test for exactly
that behaviour** in the same commit (`deck-dedup.test.ts`). This is the G2/G4
shape: the reviewer is shown one file and asked a question about the change.

| arm | manifest (T047) | context (T045/T046) | exit |
|---|---|---|---|
| A | on | on | **0** |
| B | on | off (`--no-context`) | 1 |
| C | **off** (pre-T047) | on | 1 |

Arm C restores the exact pre-T047 state — `needs_manifest=False` on the tests
reviewer — so the comparison isolates one flag.

### Read C against A, not C against B

**A reviewer of this PR caught an error in the first draft of this file**, and it
is worth recording rather than quietly correcting. The draft claimed the class
was "measured closed (arm C → arm B)". That comparison changes **two** variables
at once — C is manifest-off/context-on, B is manifest-on/context-off — so it
cannot attribute the change to the manifest.

The single-variable comparison is **C → A**: context is on in both, and only the
manifest differs. That is the comparison reported below. The conclusion is
unchanged, but the first draft's stated evidence did not support it, which is the
same defect class this spec exists to close, committed inside the audit that
closes it.

### The false positive, reproduced and closed (C → A)

**Arm C** (pre-T047, context on) produced it verbatim, at `actionable` severity:

> The new `map((n) => n.trim())` normalization changes dedup-key behavior for
> names with leading/trailing whitespace, **but the diff adds no test covering
> it**.

That is false. `deck-dedup.test.ts` is in the diff and adds precisely that test.
This is the finding that fired four times in one session against diffs whose
test files were in the same diff.

**Arm A** (post-T047, context still on, same model, same diff) produced no
claim that tests are absent. Its tests findings assess the *adequacy* of the
tests that are there — "only asserts `length` is 1", "only passes single-element
arrays" — and its `deck-dedup.ts` finding opens with what coverage
`deck-dedup.test.ts` should add, rather than asserting it does not exist.

**Arm B** (manifest on, context off) shows the same reversal in the reviewer's
own words, which is why it is quoted here even though it is not the controlled
comparison:

> **`deck-dedup.test.ts` is in this diff, but** the newly added
> `.map((n) => n.trim())` needs explicit edge-case coverage: `[' a ', 'a']`,
> internal whitespace preserved while ends are trimmed …

The finding did not disappear — it became **true, and better**. The reviewer
stopped asserting the absence of tests and started assessing whether the tests
present are adequate, which is what the manifest text instructs and what the
reviewer is actually good at.

### What the context added

Arm A produced the same three observations as arm B at **`nit` rather than
`actionable`**, and exited 0. It also produced a finding that cites the context
by name, which is direct evidence the payload was read rather than merely sent:

> Test references `offenders` from `./console-guard`; the manifest shows no files
> renamed or removed, and console-guard.ts (**present in referenced definitions**)
> exports `offenders`. No drift detected.

**Do not over-read the severity shift.** One run per arm, one model. A
categorical change — a false statement becoming a true one, C→A — survives n=1
because it is not a matter of degree. A severity distribution does not.

## The class that was NOT reproduced

The `describeThrown` return-shape false positive (gold-set **G6**) **was not
generated by any of the three arms**, including the arm with context disabled.

So this measurement cannot claim to have suppressed it. A class that does not
appear in the control cannot be shown to be absent from the treatment — that is
the same "passes for an unrelated reason" defect this spec exists to close, and
recording SC-005 as met on this evidence would be an instance of it.

What is established for G6 is narrower and still worth having:
`test_the_gold_set_corpus_delivers_the_declaration_that_refutes_g6` and
`test_the_imported_definition_is_delivered` prove the interface — `errName`,
`errMessage`, `errCode` — now reaches the reviewer. G6 asserted the function
returns `{ name, message }`. The reviewer can no longer be *unaware* of the
answer; whether it reads it is not settled here.

Reproducing G6 live needs a consumer file that calls
`describeThrown(...).errMessage` with the interface outside the hunk window. The
corpus has no such consumer — the gold set was trimmed from the original PR
diffs, and those diffs were not vendored. Adding one is follow-on work; it is
recorded here rather than quietly skipped.
