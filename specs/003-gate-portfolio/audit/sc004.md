## Two proofs that failed for real while being written

Recorded because a proof that has never failed is exactly what SC-004 distrusts.

**gitleaks did not detect its first seed.** `AKIAIOSFODNN7EXAMPLE` — the AWS
documentation example key, and the obvious thing to reach for — is allowlisted by
gitleaks 8.30.1 as a known documentation value. The scan reported `no leaks
found`. Anyone sanity-checking secret detection with that string watches the gate
never fire and concludes it works. Replaced with a synthetic GitHub PAT, verified
against the installed binary rather than inferred from the rule list.

**The shape validator inverted its own result on the two constraints that
matter.** The console-callee regex and the `$ERR` unification were reported as
"exempt: cannot be lost silently" — the opposite of true. Deleting `regex` leaves
`has: {field: function}`, from which ast-grep cannot derive a kind set, so the
mutant was unparseable and a limit of the harness was reported as a property of
the gate. Found by reading which constraints landed in each bucket instead of
trusting the green exit.

## What this run does NOT establish

- **CI does not prove the reviewer wave.** It holds no provider keys, so
  `RPV2_UNPROVEN_OK: reviewers` is set in `tests.yml` and every green CI run
  prints `1 unproven` with the gate named. The live call above was made locally.
  A CI-green badge on this repo means seven of eight gates were proven.
- **Coverage is per-fixture, not universal.** `derive_shapes.py` proves each
  constraint is load-bearing against its fixture tree. It does not prove each
  negative violates exactly one constraint — one case breaking three would cover
  all three while proving none individually. Writing negatives
  one-violation-at-a-time is still a discipline; what the validator removes is
  the failure to write them at all, which is the one that actually shipped.
- **Five constraints are waived**, each probed against inputs written to break it.
  See `rules/fixtures/raw-caught-to-logger/shape-waivers.yml`. A waiver cannot
  hide a constraint — the list is derived from the rule — and a waiver for a
  constraint that later becomes covered is a hard error.
